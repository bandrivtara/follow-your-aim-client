# Health ↔ Follow Your Aim: робочий процес харчування

Оновлено: 15 листопада 2026 року.

## Коротко

`Health` — приватна база й місце роботи Codex. `Follow Your Aim` — щоденний інтерфейс виконання. Firebase зберігає тільки операційні дані харчування; медичні аналізи, діагнози й ліки туди не передаються.

```text
Health (приватно)
  профіль → вподобання → рецепти → запаси → 14-денний план
       ↓ затверджені fya-nutrition-v2 JSON
Follow Your Aim / Firebase
  сьогодні → закупи → prep → морозилка → факт
       ↓ fya-nutrition-report-v1
Health
  аналіз → до 3 змін → наступний цикл
```

## Де зберігається правда

| Дані | Джерело правди | Не дублювати в |
|---|---|---|
| Аналізи, ліки, діагнози | приватний `Health/medical/` | Git/Firebase |
| Цілі, повний профіль | приватний `Health/00_PROFILE.md` | Follow Your Aim |
| Вподобання і відмови | `Health/nutrition/preferences-catalog.md` | ручні списки в коді |
| Перевірені рецепти | `Health/nutrition/recipes/` | компоненти React |
| Фактичні запаси | `Health/nutrition/inventory.md` | прогноз у Firebase |
| Затверджений план | Health PDF + два JSON | ручне редагування у двох місцях |
| Щоденне виконання | `nutritionDay` у Firebase | Health під час тижня |
| Тижневий факт | експорт `fya-nutrition-report-v1` | припущення з плану |

## Ролі

### Власник профілю

1. Перед циклом дає календар, тренування, події, запаси й cheat meal.
2. Разом із Катею погоджує PDF-чернетку.
3. Під час тижня позначає статуси прийомів і коротко коментує відхилення.
4. Після тижня завантажує JSON-звіт для Health.

### Катя

1. За замовчуванням їсть спільну основну страву.
2. До затвердження називає лише винятки у форматі `дата → прийом → заміна`.
3. Заміна показується біля відповідного дня; окрема дубльована таблиця не створюється.

### Codex у Health

1. Читає `AGENTS.md`, профіль, медичний контекст, вподобання, останній цикл і звіт.
2. Формує 14-денну PDF-чернетку, закупи, prep і морозильний план.
3. Після явного погодження формує фінальний PDF і два `fya-nutrition-v2` JSON.
4. Після звіту аналізує лише фактичні дані й змінює не більше трьох речей.

### Follow Your Aim

1. Показує сьогоднішні страви, ваги, калорії та БЖВ.
2. Показує операційну частину тижня: закупи, prep, розморожування, події й заміни Каті.
3. Не фіналізує неповний день і не включає його в середнє як достовірний.
4. Експортує факт разом із позначкою повноти даних.

## Щоденний сценарій

1. Відкрити `Харчування`; за замовчуванням відкритий поточний день.
2. Перевірити блок `На сьогодні`: закупи, готування або розморожування.
3. Якщо план виконано без змін — натиснути `Позначити заплановане як з'їдене`.
4. Якщо щось змінилось — виправити ккал/БЖВ або додати фактичний прийом і коментар.
5. Для пропущеної страви вибрати `Не з'їв` і коротко вказати причину.
6. Зберегти день. Минулий день синхронізується з трекером лише коли всі прийоми мають статус.

## Двотижневий цикл

1. Експорт контексту Follow Your Aim і підтвердження запасів.
2. PDF `ЧЕРНЕТКА` на 14 днів.
3. Правки власника профілю й Каті.
4. PDF `ЗАТВЕРДЖЕНО`.
5. Два JSON: понеділок–неділя кожен.
6. Імпорт JSON у Follow Your Aim.
7. Виконання, закупи, prep і коментарі.
8. Експорт двох тижневих звітів.
9. Аналіз у Health, оновлення рецептів, вподобань і фактичних запасів.

## Локальний зв'язок із приватним Health

Репозиторій Follow Your Aim публічний, тому Health не копіюється в Git. Для локальної роботи створи файл, який уже ігнорується Git:

`.codex-local/health-link.json`

```json
{
  "healthProjectDir": "C:/Users/USER/Documents/ChatGPT/Health"
}
```

Перевірка зв'язку й затверджених пакетів:

```bash
npm run health:status
```

Альтернатива для CI/іншого комп'ютера — змінна середовища `HEALTH_PROJECT_DIR`. Скрипт лише читає Health і перевіряє JSON; він не записує медичні дані у Firebase.

## Межа простоти

- Не робити двосторонню синхронізацію Markdown ↔ Firebase: конфлікти складніші за користь.
- Не вести окремий каталог рецептів у React-коді: рецепти приходять із затвердженим планом.
- Не просити Катю трекати кожен грам окремо, доки немає такої цілі; її винятки впливають на закупи й prep.
- Не рахувати неповний день як нульовий або повний.
- Не переносити медичні дані до публічного репозиторію навіть у `docs/`.
